# SpacePlan

Web-платформа для проектирования помещений в 2D/3D (концепция — как у Planner 5D).
Пользователь рисует план квартиры, расставляет мебель, меняет материалы и сразу видит результат в 3D;
смета считается в тенге.

Реализован **MVP** из спецификации (разделы 45 и 57): весь путь
`регистрация → проект → стены → размеры → двери/окна → мебель → материалы → 3D → сохранение → повторное открытие → экспорт изображения`
работает и проверен в браузере.

## Архитектура

```text
apps/web      React + TypeScript + Vite, Tailwind, Konva (2D), Three.js / React Three Fiber (3D), zustand + immer
apps/api      Node.js + Express 5 + TypeScript, PostgreSQL (pg), zod, JWT, bcrypt
packages/shared   Project JSON: типы, zod-схема, геометрия, поиск комнат, каталог, материалы, шаблоны, смета
```

Ключевое решение из раздела 37 соблюдено: **единый Project JSON** (`packages/shared/src/types.ts`) —
единственный источник данных и для 2D, и для 3D, и для сметы, и для API. Все размеры хранятся в сантиметрах,
`units` влияет только на отображение и ввод.

```text
               Project JSON (packages/shared)
              /        |          |        \
       2D (Konva)   3D (R3F)   Смета ₸   API / PostgreSQL (jsonb + версии)
```

- **Редактор.** Каждое действие — именованная команда (`AddWallsCommand`, `MoveWallCommand`,
  `MoveObjectCommand`, …) в `apps/web/src/editor/commands.ts`. Store превращает её в immer-патчи
  (прямые и обратные), история хранит патчи. Перетаскивания показываются как preview и попадают в историю
  одной командой при отпускании.
- **Комнаты.** Стены разбиваются в точках пересечений и T-стыков в планарный граф, минимальные грани графа —
  комнаты (`packages/shared/src/rooms.ts`). Площадь считается по внутреннему контуру с учётом толщины стен.
- **Backend** — модульный монолит (раздел 51): auth, projects (+ версии), catalog, materials.
  Проект хранится в `projects.data` (jsonb) и валидируется той же zod-схемой, что и на клиенте;
  площадь и число этажей денормализованы для dashboard. Оптимистичная блокировка через `baseVersion` (409 при конфликте).
- **Безопасность:** bcrypt (cost 12), короткоживущие access-токены + ротация refresh-токенов (хэши в БД),
  rate limiting на auth, helmet, CORS, параметризованные SQL-запросы, валидация всех входных данных, проверка
  data-URL превью, изоляция проектов по владельцу.

### Отличия от рекомендованного стека

- Вместо Next.js — SPA на Vite: редактор полностью клиентский (Canvas/WebGL), SSR ему не нужен.
  Лендинг при необходимости SEO легко вынести в Next.js, переиспользовав `packages/shared`.
- Вместо NestJS — Express с тем же модульным разбиением по роутерам. Для MVP это меньше кода;
  модули один-в-один переносятся в NestJS-модули.
- 3D-мебель строится процедурно из примитивов по реальным размерам объекта (GLB-моделей пока нет);
  в каталоге предусмотрено поле `modelUrl` для перехода на glTF/GLB. Текстуры тоже процедурные (`textures.ts`).

## Запуск

Требования: Node.js 20+, PostgreSQL 14+.

```bash
npm install

# PostgreSQL (или свой сервер; нужны БД spaceplan и spaceplan_test)
docker compose up -d

cp apps/api/.env.example apps/api/.env   # при необходимости поправьте DATABASE_URL / JWT_SECRET

npm run dev          # API на :4000 (миграции и сид каталога выполняются при старте) + web на :5173
```

Откройте http://localhost:5173 — можно сразу нажать «Попробовать без регистрации».

Отдельно: `npm run dev:api`, `npm run dev:web`, `npm run db:migrate`, `npm run db:seed`, `npm run build`.

## Тесты

## Горячие клавиши редактора

| Клавиша | Действие |
|---|---|
| V / W / Q / D / O / H | Выделение / Стены / Комната / Дверь / Окно / Панорама |
| Двойной клик, Esc | Завершить цепочку стен |
| Shift | Рисовать без привязок |
| R, Shift+R | Повернуть объект на 90° / 15° |
| Ctrl+D | Копия объекта |
| Delete | Удалить выделенное |
| Ctrl+Z, Ctrl+Shift+Z | Отменить / повторить |
| Ctrl+S | Сохранить (с созданием версии) |
| Колесо, пробел + drag, правая кнопка | Масштаб / панорама |
| WASD + мышь | Прогулка в 3D |
